# Couverture QA des blocs pédagogiques

Cette matrice est générée à partir des JSON publiés. Chaque ligne propose jusqu’à trois écrans sélectionnés par un rang déterministe, pour produire une couverture stable et reproductible des types de blocs.

## Constats de contrôle navigateur — session apprenant démo

- L’écran `automatisation_comptable_ia__01`, unité 1, écran 1 rend les sections génériques (`learning_section`) et le template Finance & Comptabilité avec les contenus attendus.
- L’écran 2 affiche le contrôle de connaissances Mythe/Réalité. Une réponse correcte produit le feedback puis rend la navigation suivante disponible : l’interactivité reste conservée après migration.
- Une navigation directe vers une unité séquentiellement verrouillée rendait auparavant une zone vide. Le lecteur affiche désormais un état **Unité verrouillée** et un bouton **Reprendre l’unité n** ; ce comportement est volontaire et évite de confondre verrouillage pédagogique et défaillance de rendu.
- Les contrôles de familles hors source Novasavo doivent respecter le verrouillage séquentiel. Ils sont tracés comme vérifiables par cohérence interne lorsque la référence fournisseur n’est pas disponible.
- La session apprenant démo a été restaurée dans le navigateur pour contrôler des échantillons réels. La sonde Playwright conserve les URL, captures, largeur et état verrouillé, mais ses lots doivent rester limités : le chargement de nombreuses formations en une seule session peut dépasser les limites de débit destinées aux appels métier. Un résultat limité est maintenant signalé comme tel et ne doit jamais être interprété comme un bloc absent.
- L’échantillon `databricks_with_the_python_sdk__01`, leçon 1 écran 4, rend le bloc `cloud_exercise` sans modification de la bibliothèque : objectif, préparation, code de départ, ressource locale, étapes, indice, champ de preuve et verrou de navigation sont visibles. Ce contrôle confirme que le cadre générique ajouté autour des blocs ne remplace pas un TP existant.
- L’échantillon `initiation_automatisation_workflows_n8n__01`, leçon 1 écran 1, rend le bloc vidéo Projector : commandes de lecture, navigation de slides, PDF local, transcription segmentée, marquage manuel et navigation pédagogique restent opérationnels. Le contrôle confirme qu’aucun thème ou cadre générique n’a modifié la structure média existante.
- L’échantillon `claude_certified_developer_foundations__01`, leçon 1 écran 2, rend un écran de contenu long avec ancres de section, badges de niveau et navigation de chapitre. La mise en page demeure lisible, la progression de cours est cohérente et le cadre de template n’a pas dupliqué de média ni d’illustration.
- La route de l’échantillon `bucket_sort` de la seconde leçon Claude reste inaccessible au compte démo tant que le premier cours n’est pas terminé. Le contrôle est correctement expliqué comme **Cours verrouillé** avec un retour vers la certification ; cet état est enregistré comme contrainte de progression, non comme échec de rendu du bloc.
- Avec la session administrateur, l’échantillon `claude_certified_developer_foundations__02`, leçon 1 écran 8, rend le contenu multi-section, les cartes à retourner, le checkpoint `bucket_sort` et ses quatre zones de dépôt. Les cartes sont présentes, le texte d’instruction explique l’interaction et la navigation reste verrouillée tant que les cartes ne sont pas retournées et classées. Le lien d’édition est visible uniquement grâce au rôle administrateur, conformément au contrôle d’accès attendu.
- L’échantillon `working_with_the_openai_api__01`, leçon 1 écran 3, rend le bloc `code_repl` avec ses commandes Exécuter, Réinitialiser et Voir la solution. La description importée qui contenait des séquences `\\n` est désormais convertie en paragraphes lisibles, sans modifier le code de départ ni la solution. Ce correctif s’applique à toutes les consignes de blocs de code.
- L’échantillon `advanced_rag_evaluation_specialist__03`, leçon 2 écran 4, rend un checkpoint à choix unique. La première bonne réponse sélectionnée est conservée, le feedback de réussite est présent dans le DOM et les options conservent leur état visuel. Ce contrôle confirme l’interactivité d’un QCM historique hors du pilote générique.

## Matrice automatisée consolidée

La sonde administrateur `check-block-qa-samples.mjs` a parcouru les **24 types de blocs publiés** sur un écran distinct par type. Elle a été exécutée sur desktop (`1440 × 1000`) puis mobile (`390 × 844`). Chaque résultat vérifie le montage d’au moins un élément `data-block-type` correspondant, l’absence de verrou inattendu, l’absence de réponse 429 et l’absence de débordement horizontal.

| Interactions contrôlées manuellement | Mythe/Réalité, QCM checkpoint, tri, exercice de code |
